# PLC 监控中心（WPF · Modbus TCP 上位机）

基于 **Modbus TCP** 协议的 PLC 监控上位机，支持多设备管理、寄存器读写、运行状态监控、数据记录与报警管理。内置仿真 PLC，无需真实设备即可完整体验全部功能。

## 功能一览

| 模块 | 说明 |
|------|------|
| 设备管理 | 多台 PLC 设备增删改查，IP/端口/单元号/轮询周期可配，逐台或一键启停监控 |
| 实时监控 | 按点表（标签）轮询刷新，支持 Bool/16 位/32 位/Float、字序交换、工程量缩放（值 = 原始值×Scale+Offset） |
| 寄存器读写 | 读 01/02/03/04 功能码（自动分块，位≤2000、寄存器≤125）；写 05/06/0F/10，写后自动回读 |
| 状态监控 | 在线/连接中/重连中/重连失败状态灯、成功/失败计数、轮询耗时统计、连接时长与心跳显示 |
| 自动重连 | 连接丢失自动重连（指数退避 3s→30s，可配最大次数），重连失败/恢复均有报警，恢复后自动补读 |
| 心跳检测 | 空闲期周期性轻量读（间隔/线圈地址可配），及时发现半开/僵死连接 |
| 数据记录 | 每轮轮询追加 CSV（logs/data/设备_日期.csv），内置预览与打开目录 |
| 报警功能 | 每标签多条阈值规则（>、<、=、≠、≥、≤ × 三级级别），触发/恢复/确认闭环，声音提示，历史落盘（logs/alarms/） |
| **AI 问答** | 侧边栏第 5 项，用中文直接问“1号设备情况怎么样”“反应釜温度多少”，本地大模型读取实时数据后作答；工具调用过程全程可见，写入需手动授权 |

## 运行

```bash
dotnet run
```

首次运行自动生成演示配置：1 台仿真 PLC（含温度/压力/电机/计数器等标签和报警规则）+ 1 台未连接的示例真机（演示通讯异常报警）。启动后侧边栏「▶ 启动全部监控」即可看到实时数据。

接入真实 PLC：设备管理 → 新增设备 → 取消勾选"仿真设备" → 填写 IP/端口 → 配置点表。

### AI 问答的前置条件

侧边栏「AI 问答」依赖同目录下的 **Ollama 便携版**（本项目位于 `Ollama-Harness` 工程内时会自动定位）。
程序启动时若发现本地服务未运行，会**自动后台拉起** `ollama serve`。

若尚未拉取模型，先在 `Ollama-Harness` 目录执行：

```bash
python scripts\pull_model.py qwen2.5:3b
```

> 注意：本机 `ollama pull` 会在写 manifest 时失败，必须用这个脚本，详见 `Ollama-Harness/README.md`。

CPU 推理较慢，首次提问约需 20~40 秒（含模型加载与多轮工具调用）。

## 架构

```
WpfApp20/
├── Core/Mvvm.cs                  # ObservableObject / RelayCommand（零依赖 MVVM）
├── Models/Models.cs              # 设备/标签/报警规则/应用配置（JSON 持久化）
├── Modbus/
│   ├── ConnectionManager.cs      # Modbus 通信管理器：自动重连（指数退避）+ 心跳检测
│   ├── TcpModbusClient.cs        # NModbus 3.x 真实 Modbus TCP 主站
│   ├── SimulatedModbusClient.cs  # 内置仿真 PLC（按点表语义生成协调波形）
│   └── ValueCodec.cs             # 数值编解码：类型/字序/缩放
├── Services/
│   ├── DeviceManager.cs          # 多设备轮询引擎（每设备一通信管理器，串行化访问）
│   ├── AlarmEngine.cs            # 报警评估/触发/恢复/确认
│   ├── DataLogService.cs         # CSV 数据记录与报警落盘
│   ├── ConfigService.cs          # config/appconfig.json 读写 + 默认演示配置
│   ├── RuntimeModels.cs          # DeviceRuntime / TagValueItem / AlarmRecord（UI 绑定）
│   ├── PlcTools.cs               # 供大模型调用的工具集（设备/点位/报警/统计/写入）
│   ├── LlmClient.cs              # 本地 Ollama 客户端：服务探测拉起 + 流式对话 + 工具调用协议
│   └── AiAssistant.cs            # 工具调用 Agent 循环 + 幻觉护栏
└── Views/                        # 设备管理 / 实时监控 / 报警中心 / 数据记录 / AI 问答 + 编辑对话框
```

关键设计：

- **ModbusConnectionManager（每设备一个）**：管理连接完整生命周期——
  - **自动重连**：连接丢失后按指数退避（`base×2ⁿ`，上限 30s）自动重试，可配最大次数（0=无限），超限进入"重连失败"并报警；每次重连失败/恢复都有事件上报，恢复后立即补一轮读取。
  - **心跳检测**：空闲期周期性读取 1 个线圈（地址可配），及时发现半开/僵死连接，失败立即触发重连。
  - **错误分级**：Socket/IO/超时 → 连接级（重连）；Modbus 异常响应 → 操作级（只记失败，保持连接）。
  - **串行化**：轮询/写值/心跳/重连共用一个信号量，杜绝并发事务冲突。
- **分块读取**：同区域标签按地址排序合并成块（位 ≤2000 / 寄存器 ≤125），超限自动拆分，减少报文往返。
- **配置即点表**：所有设备/标签/报警规则/重连与心跳参数保存在 `config/appconfig.json`，重启自动恢复。

## AI 问答设计

### 为什么用工具调用，而不是把数据塞进提示词

数据全量注入会随点表规模膨胀而失控，且无法保证读到的是提问那一刻的值。
这里采用 **function calling**：把 PLC 数据封装成工具交给模型，模型自行决定读哪些点，
由 `AiAssistant` 执行工具、把结果回传，直到模型给出最终答案（最多 4 轮）。

所有取值都在 **UI 线程做一次快照**（`PlcTools.SnapshotAll`），再交给后台线程使用，
避免跨线程直接操作 `ObservableCollection`。

### 可用工具

| 工具 | 作用 |
|------|------|
| `list_devices` | 设备清单：编号、状态、点位、通讯统计 |
| `get_device_data` | 指定设备的全部点位实时值 |
| `query_tags` | 按关键词跨设备检索点位 |
| `get_active_alarms` / `get_alarm_history` | 活动报警 / 报警历史 |
| `get_device_stats` | 通讯质量：成功率、耗时、最后错误 |
| `get_tag_history` | 当日 CSV 中的最近采样，用于看趋势 |
| `write_tag_value` | 向可写点位下发数值（需界面授权） |

### 三道防幻觉护栏

小模型在数据准确性上不可轻信，因此加了确定性兜底，全部经真实提问验证：

1. **未调工具兜底**：数据类问题（命中设备名/点位名/数据关键词）却一次工具都没调 →
   由 `PlcTools.RetrieveFor` 自行取数，再让模型严格依据真实数据重答。
   *（实测：不加固时"反应釜温度是多少？"被答成 21.002℃，真实值当时是 15.x℃）*
2. **离线不报数**：设备未连接时，工具返回的是"上一次的残留值"。此时一律输出
   `（离线，无有效读数）` 并附警示，禁止模型把它当实时值。
   *（实测：加固前把离线 2#线残留的 0 当成了液位读数）*
3. **漏查设备提醒**：多设备场景下若某次调用被设备名收窄，工具结果尾部追加提示，
   提醒模型留下 device 为空重新查询。
   *（实测：加固前问"所有设备通讯正常吗"只查了 1#线，得出"全部正常"的错误结论）*

此外模型侧还压低了随机性（`temperature 0.2`）并限制篇幅，避免临场发挥。

### 写入安全

`write_tag_value` 默认**关闭**。必须在界面勾选「允许 AI 写入 PLC」后才会真正下发，
且会二次校验该点位是否属于可写区域（线圈/保持寄存器）。

## 数据文件

- `config/appconfig.json` — 设备与点表配置
- `logs/data/<设备名>_<yyyyMMdd>.csv` — 轮询数据
- `logs/alarms/alarms_<yyyyMMdd>.csv` — 报警事件（触发/恢复/确认）

## 依赖

- [.NET 10](https://dotnet.microsoft.com/) + WPF
- [NModbus 3.0.83](https://www.nuget.org/packages/NModbus)（Modbus TCP 协议实现）
