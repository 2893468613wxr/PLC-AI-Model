## WpfApp20：PLC 监控上位机（WPF + Modbus TCP）从零搭建

用户要求：基于 Modbus TCP 的 PLC 监控上位机，含多设备管理、寄存器读写、状态监控、数据记录、报警。

### 完成内容
- 技术栈：.NET 10 WPF + NModbus 3.0.83 + 零依赖 MVVM（手写 ObservableObject/RelayCommand）
- 分层：Models / Modbus(通信) / Services(引擎) / Views(UI)，深色工业风主题（App.xaml 全局样式）
- 通信：TcpModbusClient（NModbus 主站）+ SimulatedModbusClient（内置仿真 PLC，按点表语义生成波形，无需真机）
- 轮询引擎：每设备一个 DeviceWorker（独占连接 + SemaphoreSlim 串行化），分块读取（位≤2000/寄存器≤125），断线重连
- 值编解码 ValueCodec：Bool/16/32 位/Float、WordSwap 字序、Scale/Offset 工程量换算
- 报警：AlarmEngine 每标签多规则（6 种操作符×3 级别），触发/恢复/确认闭环，声音提示，CSV 落盘；设备断线产生"严重"级通讯报警
- 数据记录：logs/data/设备_日期.csv，报警 logs/alarms/alarms_日期.csv；数据记录页可预览 CSV
- 配置持久化 config/appconfig.json，首次运行注入演示配置（仿真 PLC 1#线 + 未连接示例真机）

## WpfApp20：Modbus 通信管理器（自动重连 + 心跳检测）

用户要求：添加自动重连机制（Modbus 通信管理器，支持自动重连和心跳检测）。

### 完成内容
- 新增 `Modbus/ConnectionManager.cs`：ModbusConnectionManager，每设备一个
  - 状态机：已断开→连接中→已连接→重连中→重连失败，事件驱动（StateChanged/ConnectionLost/ConnectionRestored/ReconnectAttemptFailed/ReconnectGaveUp/HeartbeatTick）
  - 自动重连：指数退避 base×2^(n-1)，上限 30s；MaxReconnectAttempts=0 表示无限；超限进入"重连失败"并报警
  - 心跳检测：空闲期每 HeartbeatIntervalMs 读 1 个线圈（地址可配），失败立即进入重连；与轮询共用信号量，gate 忙时跳过
  - 错误分级：Socket/IO/Timeout/ObjectDisposed/InvalidOperation → 连接级（重连）；NModbus SlaveException 等其余 → 操作级（仅记失败）
- DeviceWorker 重构：轮询/写值全部走 Conn.ExecuteAsync（统一超时 10s/5s，连接不可用返回 Skipped 不计失败）；恢复连接后立即补一轮读
- DeviceConfig 新增 6 个配置项：AutoReconnect/MaxReconnectAttempts/ReconnectBaseDelayMs/HeartbeatEnabled/HeartbeatIntervalMs/HeartbeatAddress
- UI：设备编辑对话框新增"通信管理"卡片；设备列表新增"连接信息"列（连接时长/心跳/重连倒计时，1s 定时刷新）；新状态灯颜色（重连中=橙、重连失败=红）
- TcpModbusClient：反射设置 NModbus master Timeout=3s（防无响应挂死，跨版本兼容）
- 报警：连接中断/连接失败/重连放弃 → 严重级通讯报警（去重）；恢复时自动记录"恢复"

### 端到端实测（迷你 Modbus TCP 从站）
pymodbus 3.15 API 大改（datastore 全 deprecated），改手写 ~90 行 socket 从站（FC1/2/3/4/5/6/16）做真实 TCP 测试：
1. 连接正常：Float 液位解码正确（16.17→18.5 平滑变化），2s 轮询
2. 杀从站：1s 内检测到连接中断（"远程主机强迫关闭"），严重报警触发，数据记录停止
3. 重启从站：37s 后按退避序列（2/4/8/16s）自动重连成功，报警自动"恢复"，数据无缝续记

### 踩坑记录
- pip 默认走清华镜像源不可达，需 `-i https://pypi.org/simple` 指定官方源
- pymodbus 3.15：ModbusSlaveContext/StartTcpServer 已废弃且签名全变，新 API SimData 未稳定——测试用 Modbus 从站不如手写 raw socket
- 心跳与轮询抢同一 gate：用 `_gate.CurrentCount == 0 → skip` 避免排队堆积
- 测试后记得把 bin 目录 config 恢复为演示配置，避免用户下次启动连不上测试地址

## WpfApp20：博图（TIA V16）仿真测试方案

用户无实体 PLC，装了博图 V16，问能否用它测试 + PLC 测试程序怎么写。
- 结论（已查证西门子官方）：**普通版 PLCSIM 不支持 Modbus TCP 对外通信**，必须用 **S7-PLCSIM Advanced V4.0**（配 V16），需 Win10/11 专业版 + 虚拟化 + 授权（21 天试用）
- 产出《博图PLCSIM测试指南.md》：完整方案含 PLC 侧程序（SCL）
  - MB_SERVER 映射规则：保持寄存器→MB_HOLD_REG 指向的非优化 DB（40001=DBW0）；线圈→Q 区（00001=Q0.0）；离散输入→I 区；输入寄存器→IW 区
  - **西门子 MB_SERVER 默认只响应 Unit ID=255**，上位机单元号须填 255
  - S7 Real 大端 ABCD → 上位机浮点标签不勾字序交换
  - TCON_IP_v4：ConnectionType=11(TCP)、ActiveEstablished=FALSE、LocalPort=502、InterfaceId=PROFINET HW ID（填错报 0x80C8）
  - PLCSIM Advanced 必须选 TCP/IP 模式（Softbus 外部程序连不上），虚拟网卡同网段
  - 测试矩阵含断线重连（Stop/Start 实例）与非法地址（操作级错误不触发重连）
